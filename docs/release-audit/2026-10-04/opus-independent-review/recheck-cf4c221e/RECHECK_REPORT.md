## Confirmed product finding

**P2 — iOS backup import supplies a MIME string to a UTType-identifier API.** `apps/mobile/src/state/backupStore.ts:80` sets `MIME='application/octet-stream'`; `backupStore.ts:610` supplies that value to `picker.pick` on both platforms. Opening a portable backup uses this path before authenticated preview/restore. Installed, lock-pinned `@react-native-documents/picker` is **12.0.2**. Its actual `src/pick.ts:114–140` only normalizes the string into an array and forwards it unchanged. Its iOS `ios/swift/PickerOptions.swift:31` constructs content types with `types.compactMap { UTType($0) }`; line59 supplies that array to `UIDocumentPickerViewController`. This constructor takes a type identifier, rather than converting a MIME tag. The package's `src/fileTypes.ts:24` uses `public.item` for all files on iOS and `*/*` on Android. These platform contracts are also described in the package's primary [file-type documentation](https://react-native-documents.github.io/docs/sponsor-only/picker/limiting-selectable-files) and [Apple's UTType initializer](https://developer.apple.com/documentation/uniformtypeidentifiers/uttype-swift.struct/init%28_%3A%29).

The independently owned probe compiles the exact production `pickerOpen` declaration and loads the installed picker JavaScript, including its real option normalization and cancellation helpers. Only the React Native/native picker seam is mocked. The actual captured native options on iOS are `type:['application/octet-stream']`; the installed platform default is `public.item`. Android receives the MIME string as expected. Native cancellation returns null without proceeding to private copy on both controls. The normative iOS type assertion fails with **exit1**, as intended. Evidence: `picker-native-boundary-probe.cjs`, `picker-native-boundary.json`, `picker-native-boundary.log`. This defect is unchanged from the accepted559 source and was missed by prior tests that mock the whole picker. It is not a regression introduced by the current boot delta.

**Actual UIKit outcome has not been observed by this Windows lane.** No native crash, empty picker or failed tap is claimed. The caller/native API mismatch itself is confirmed. Close it at the existing shared picker boundary using the installed library's platform-aware type, preserving Android filtering and authenticated-format validation. Retain selected URI/type, result/state and exact artifact/source identity without athlete secrets. Parent has already sent the concrete fix and native verification request to the existing Opus job.
