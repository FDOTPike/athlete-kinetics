## What Round 2 remediates (owner's seven required items)

1. **Power-specific, gate-safe selection + athlete-facing explanation.** The classification is
   NOT invented: it reads the owner-curated `movement_lift_family` rows whose
   `preferred_purpose = 'speed'` (migration 052) — Speed Box Squat, Kettlebell Seesaw Press,
   Double Kettlebell Push Press, Power Clean. The store threads those names into every
   generation path as `powerPreferredMovementNames`; the ranker orders gated-available
   speed rungs first for the power objective only. This is a preference among already-gated
   candidates, never a gate: tier/equipment/safety/capability/attestation bind exactly as
   before, and **an intermediate is never handed Power Clean** (proven in
   verify_programQualityRound2.mjs [P1] and matrix PQ-06). The athlete-facing copy is the
   pure `powerObjectiveExplanation` export, rendered by ProgramSetupScreen — the UI and the
   evidence harness cannot drift.
2. **Hypertrophy dose roles.** `ROUND2_HYPERTROPHY_ROLE_SET_DELTA = -1` (named, documented,
   exported): accessory slots (slot_index ≥ 3, the pre-existing ACCESSORY_SLOT_FROM law) carry
   one fewer working set than primaries on hypertrophy strength days; the 2-set floor and the
   deload halving are boundary-tested. Accessory slots also prefer non-compound candidates, so
   the dose role and the movement class align visibly. The −1 value reuses the engine's own
   established unit (the hybrid accessory tax), so no coefficient was invented. Overload path:
   the schema progression (weeks 1–3) plus the deload cut, now named in the preview summary.
3. **Progression summary rendered.** `weeklyProgressionSummary` output now appears in the
   actual ProgramSetupScreen preview (`weekly-progression-summary` card) for the week 1→2 and
   3→4 transitions of every representative slot, resolved against the real store movements.
4. **Pure capacity calculation.** `strengthAnchorCapacity` counts squat/push_h/hinge plan
   slots after duration shaping (slot budget = clamp(round(minutes/22), 2, 5), the generator's
   own law) and focus shaping (programFocuses). The `days < 3` heuristic is gone; the setup
   screen's warning consumes the imported function. Boundary sweep 1–7 days × {15, 90, 240}
   minutes is machine-checked.
5. **Limitations screen gate.** NEXT is disabled on the limitations screen until the athlete
   explicitly presses Yes or No; the rule is stated on-screen ("Choose YES or NO to
   continue…"). Draft state, back navigation, and the single atomic `completeOnboarding`
   Finish are byte-preserved (existing tests updated only to answer the gate they traverse).
6. **Progression methodology disclosed.** The review screen's coach-defaults block now names
   `Progression method: <label>` alongside effort ceiling, sessions/day, and energy focus —
   every removed advanced default is disclosed in one place.
7. **Matrix rebuilt.** PQ-01–PQ-14 regenerated by `matrix_harness.mjs` from the candidate
   code; 14/14 PASS with no unconditional rows (PQ-12/13 reference their named component
   tests, which run in verify:components). PQ-04/05/06 are semantic:
   - **PQ-04** runs the real capacity law AND the real generator at the shaped schedule,
     requiring capacity < 3, fewer than three anchors carried, and every absent anchor
     gate-disclosed.
   - **PQ-05** proves the bodybuilding contract: zero big-three, balanced squat/push_h/pull_h
     exposure, primary 4 sets vs accessory 3 sets (roles distinct), non-compound accessory
     share reported, overload named by the progression summary.

     (Speed Box Squat, Double Kettlebell Push Press), Power Clean count 0 for an intermediate,
