## 3. The finding, and why it matters more than limit cycling

The response sign is **persistence, not reversal**: a cut yields `φ = +0.2788`
(deficit → cut again), a raise yields `φ = −0.2777` (headroom → raise again).
One-step reversal would require `Δφ ≤ −0.30` / `≥ +0.30`; the observed signs are
opposite.

Mechanism (§6) is specific and checkable: corrections act in weeks 1–3, but the
21-day boundary window spans block days 7–27. Its **old** 7-day sub-window holds
the strongly-corrected week-2 errors; its **recent** sub-window holds the
**uncorrected week-4 deload**. So an improving cut reads as a positive trend and
a decaying raise reads as a negative trend. The trend channel reinforces the
relay's prior direction.

This is a ratchet, not a chatter — and it is the failure mode the prior audit
could not have found, because an oscillation-only test reports it as stable.

## 4. Notes for C3

### 4a. The persistence sign is deload-phase dependent — vary the alignment

The whole §6 mechanism rests on week 4 being uncorrected deload while the trend's
recent window sits on it. That makes the sign a function of **window/deload phase
alignment**, not a property of the controller alone. If a macro phase places
deload differently, omits it, or if the block boundary shifts the window offset,
the sign could flip — and a flipped sign is the reversal case.

C3 should vary deload placement and block-boundary offset explicitly. As it
stands the result is "persistence for this alignment", which is narrower than it
reads.

### 4b. One pattern, one template

Evaluated: strength / intermediate / 4 sessions per week / LINEAR / macro block 3
/ squat at 2×/week, observer indices `[0,3,7,10,14,17]`. Low-frequency patterns
(carry, rotation, isolation) yield fewer observations, changing trend-window
composition and approaching `MIN_OBSERVATIONS = 5`, below which everything
collapses to neutral regardless. Cover at least one low-frequency pattern.

### 4c. The local result predicts departure from where it is valid

§1 declares a linearisation about **zero observer error**, before RPE clamping
and `E_MAX` branch changes. But the finding is that the system moves *away* from
neutral and keeps going. So the analysis is valid precisely where the system does
not remain. The interesting dynamics — clamping, `E_MAX` saturation, the
monotone-conservative override firing — all live at the operating points this
model excludes. Sol says as much; C3 has to actually go there.

### 4d. Name the practical consequence, and check the asymmetry holds

If persistence survives C3, the reading is: **the controller ratchets.** Worth
noting that the shipped code already rations one direction — §2 records that
`generateBlock` grants a positive set addition once per pattern per block but
applies negative set cuts at every occurrence, and `MAX_ADDED_SETS = 2` caps
additions globally. So the set channel ratchets **down faster than up**, which is
the correct safety asymmetry.

The RPE channel appears to carry no such rationing: `dRpe = ±0.5` at every
non-deload slot in both directions. If so, a healthy athlete with no niggles —
therefore no monotone-conservative override — could ratchet **up** +0.5 RPE per
block toward `base_rpe_cap` on a trend signal that is a deload artefact. C3
should confirm or refute that specifically; it is the safety-relevant direction
and the clamp at `base_rpe_cap` is the only thing stopping it.
