# C5 audit — R1 cumulative RPE authority budget (Claude pass)

Verdict: **GO on the design, conditional on one fix.** One fail-open default on
the authority-raising path (§3). Two questions for Francis at ratification (§4).

First change to shipped controller source in this chain, so this audit reads the
code rather than the report.

---

## 1. Verified in source

- **`verify_autopilot.mjs` was extended, not weakened.** The single modified
  assertion is *strengthened* — the halt check now also requires
  `blockAddedRpe === 0`. Everything else is additive: the 0.5/0.5/0×6 grant
  schedule, worst-case cumulative `= MAX_MACROCYCLE_RPE_RAISE`, cuts unrationed
  at macro block 8, and rollover reset. This was the main risk in touching
  shipped controller code and it was handled correctly.
- **Safety precedence preserved.** Halt returns early at `:373` with
  `blockAddedRpe: 0`, before both authority passes. The monotone-conservative
  override runs in pass 1, ahead of the pass-3 budget. Order is right and now
  machine-checked.
- **Observer untouched.** No flaw-detection formula or constant changed, so the
  analytic φ pins survive intact — the reason for sequencing R1 first.
- **No hidden state.** Pass 3 reads the already-persisted `macroBlockIndex`;
  rollover 8→1 releases the next cycle's grant with no migration and no
  in-memory accumulator. Elegant.
- **Both enforcement points bounded.** `deriveControlAction` picks *which*
  pattern gets the grant (lowest φ, declaration order breaks ties);
  `generateBlock:369` applies it to at most one planned slot. That closes the
  original defect where `±0.5` reached every non-deload occurrence.

## 2. The suppression is honest, and labelled as such

`authority_limited_neutral` as a trajectory label distinct from
`converged_neutral` — 1,855 cases — is the right call. It does not claim the
controller settled; it records that the controller wanted to act and was not
permitted to.

§5 is explicit: nominal φ stays at `-0.299` and *"R1 suppresses it after the
bounded grant rather than fixing it."* Correct, and worth restating plainly:
**the 14 limit cycles did not resolve, they lost a leg.** The converted cases in
§4 read `N,C,N,N,N,C,N,C` — cuts still fire, raises cannot. Alternation is
broken by disabling one direction, not by correcting the signal. R2 remains
necessary and R1 does not reduce its priority.

## 3. Required fix — the macro index default is fail-open

```ts
macroBlockIndex: number = 1,
...
const normalizedMacroBlockIndex =
  Number.isFinite(macroBlockIndex) ? Math.max(1, Math.round(macroBlockIndex)) : 1;
const grantsThisBlock = normalizedMacroBlockIndex <= macroGrantSlots ? 1 : 0;
```

Both the parameter default and the non-finite fallback resolve to `1`, and
`1 <= 2`, so both **grant a raise**. Unknown state opens upward authority.

This contradicts the module's own stated rule. `kinematicAutopilot.ts:371`
handles thin or non-finite φ by emitting neutral, commented: *"it must never fall
through the φ-ladder into the authority-RAISING terminal branch."* Pass 3 does
exactly that.

No live defect today — `blockGenerator.ts:362` is the only shipped caller and it
passes the index. The exposure is future callers, and a corrupt persisted
`macroBlockIndex` reading NaN, which would release a grant every block.

Fix: fall back to a no-allowance value (`macroGrantSlots + 1`) rather than 1, or
make the parameter required. Add the matching pin: *non-finite `macroBlockIndex`
grants zero RPE.* Two lines and one check.

## 4. For Francis at C5

**4a. Is "no upward autopilot correction after week 8" the intended product
behaviour?** Blocks 3–8 is 24 of 32 weeks with zero upward RPE authority. The
mitigation is that the autopilot is a *corrective overlay* — planned progression
still comes from `progressionEngine` and the scheme tables, so athletes progress
on plan; what is disabled is the autopilot adding to it. That is probably right,
but it is a product decision and should be made deliberately rather than
inherited from a remediation.

**4b. `MAX_MACROCYCLE_RPE_RAISE = 1.0` is calibrated against a broken observer.**
The observer systematically over-reports headroom because of the deload straddle.
R1 counteracts that by suppressing raises. **Once R2 corrects the observer, this
budget will be limiting correct headroom signals** — a controller that stays
permanently over-conservative for a reason that no longer exists.

Record now, as an explicit R2 obligation, that `MAX_MACROCYCLE_RPE_RAISE` and the
`0.5,0.5,0,0,0,0,0,0` schedule are revisited once the observer is fixed. They are
currently compensating for a bug, not expressing a safety policy. Neither value
carries a stated rationale in `CONTROL_AUTHORITY` — add one.

## 5. Evidence quality

2,385 cases rerun twice deep-equal. Transition table accounts for every case
(2,385 → 2,385). The 206 downward-saturation cases and single downward ratchet
are unchanged, exactly as predicted by cuts remaining unrationed — a good
internal consistency check. RPE-cap binding 1,911 → 0. Counterexample gate
reports 7 deliberate conversions and 11 expected passes, so the XPASS mechanism
did its job.

## A2. Coverage note — the bounded-authority sweep no longer reaches +0.5

`verify_autopilot.mjs:337` still calls `deriveControlAction(..., NEUTRAL_PROFILE,
GPP)` with three arguments inside the φ-sweep pin. The file is `.mjs`, so the
now-required fourth parameter is not enforced at runtime — it arrives as
`undefined` and correctly fails closed.

Consequence: every positive `dRpe_p` in that sweep is zeroed, so the assertion

```
'per-pattern: dSet∈{-1,0,1}, dLoad∈{0.95,1,1.05}, dRpe∈{-0.5,0,0.5}, pref∈{-1,0,1}'
```

now only ever observes `dRpe ∈ {−0.5, 0}`. It still passes, because `0` is in the
permitted set — but it no longer exercises the domain its name advertises.

Not a correctness hole: the `+0.5` grant is covered explicitly by the R1 pins
(`R1 block grant is one RPE_STEP, kept by lowest φ`, and the
`[0.5,0.5,0,0,0,0,0,0]` schedule check, both of which pass real indices).

But it is the same shape as the defect this whole exercise started from — a pin
that appears to test something it silently stopped testing, exactly like the
λ-blind φ pins at `verify_autopilot.mjs:15`. Pass `1` as the fourth argument in
that sweep so it covers the full output domain. Fold into R2 cleanup; not worth
reopening R1a.
