## 1. Corrections to my own prior analysis

**My open-loop hypothesis was wrong.** `WORKORDER_Sol_autopilot_stability.md` §4
proposed that Neo's null result came from a loop that never closed. Sol ran the
four-link test and all four hold: forced `dRpe = −0.5` → dose 0.75→0.70 →
first-session ΔRPE change −1.557 against a plant-equation prediction of −1.557 →
φ 0.6451→0.6420, independently reproduced to round4. The loop is closed. The
harness structure is salvaged, correctly.

**The real mechanism is saturation at the observer input, and it is a cleaner
explanation than mine.** Neo set `BASE_CAPACITY = 5.0` against a target RPE of
7.5 with `RPE_GAIN = 3.0`:

```
clamp(7.5 + 3.0 × (7.5 − 5.0), 1, 10) = clamp(15.0, 1, 10) = 10.0
```

The athlete is maxed from day one. Worse, Sol found the harness stored the
**unclamped** `rpeDelta = 7.5` rather than the observable `actual − target = 2.5`.
Since `E_MAX = 3.0`, `min(7.5, 3.0) = 3.0` — pinned at maximum deficit
permanently. That is a double saturation: wrong quantity, and above the cap.

This fully explains Neo's reported figures. `φ_base = 1.0` gives
`φ = 0.7 + trend`, which lands squarely in the reported max |φ| band of
0.8232–0.8929. Nothing could oscillate because φ could never return through the
deadband. **Neo's "no limit cycling across the entire plant family" is an
artefact of a broken plant initialisation, not a property of the controller.**

## 3. Notes — for C2, not blockers on C1

### 3a. Sweep the initial condition, not `BASE_CAPACITY`

Fixing `BASE_CAPACITY_RPE = 7.5` is defensible: it defines the neutral point
where a 7.5 target yields zero error, so it is a definition rather than a free
parameter. Sweeping it would just start the athlete in deficit or surplus, which
is what the fitness/fatigue state already expresses.

But that reasoning has a consequence. With `fitness = fatigue = 0` at t=0, every
run begins at **exactly** neutral — the friendliest possible start for a
stability test. Nonlinear systems can be stable from one initial condition and
limit-cycle from another. Sweep initial fitness/fatigue offsets (mid-deficit,
mid-supercompensation) instead. That is the robustness question
`BASE_CAPACITY` was standing in for.

### 3b. C2 must model BOTH control channels, at their different lags

This corrects my own §6b estimate. The relay fires `dRpe` and `dSet`
simultaneously, and under the ratified dose formula they have very different
plant authority:

```
slotDose = (sets / 4) × (target_rpe / 10)

−0.5 RPE at 4 sets:  0.750 → 0.700   (−6.7%)
−1 set at RPE 7.5:   0.750 → 0.5625  (−25.0%)
```

The set channel carries roughly **3.7× the dose authority** of the RPE channel.
My ≈1.2 first-order boundary modelled only `δe = 0.5 · RPE_GAIN` — the RPE
channel alone. The true per-step perturbation is materially larger, so the real
boundary is likely **below 1.2**. The 0.25 envelope floor is well chosen.

More importantly, the two channels act on **different timescales**:

- `dRpe` moves the target directly → ΔE shifts within the same window. Fast.
- `dSet` changes dose → fatigue over ~τ_fat → capacity → ΔE. Slow.

That is a phase-lag structure, and phase lag is the classic driver of limit
cycles. A scalar single-channel treatment will miss it. C2 should carry both
channels with their lags rather than collapsing to one perturbation.

### 3c. Determinism must be checked at `SIGMA_RPE > 0`

`SIGMA_RPE` floors at 0, which is right for deterministic isolation. But a
double-run deep-equality check at σ=0 is trivially satisfied by a plant with no
stochastic term. Run the determinism gate at σ > 0 with a seeded PRNG, or it
asserts nothing about seeding.
